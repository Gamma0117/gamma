# Claude Code에 보낼 프롬프트 모음

그대로 복사해서 쓰고, `P0-1` 같은 번호만 바꾸면 된다.

## 1. 맨 처음 한 번

```
CLAUDE.md, docs/ROADMAP.md, docs/22_p0_tech.md를 읽어줘.
아직 코드는 쓰지 말고, 이해한 내용을 5줄로 요약한 뒤
P0-1(빌드 환경, 창 띄우기)의 계획을 보여줘:
만들 파일 목록, vcpkg.json 의존성, CMakePresets 구성, 완료 확인 방법.
```

## 2. 매 작업 시작 (계획 모드에서)

```
docs/ROADMAP.md의 P0-3만 진행할 거야. 관련 문서(CLAUDE.md의 표 참고)를 읽고
바꿀 파일, 새 타입·함수, 테스트, 내가 직접 확인하는 방법을 계획으로 보여줘.
승인하기 전에는 코드를 쓰지 마.
```

계획을 읽고 괜찮으면: `좋아, 진행해.`

## 3. 작업 마무리

```
빌드와 테스트를 모두 돌려서 통과하는지 보여줘.
그다음 ROADMAP 체크박스를 갱신하고, 내가 실행해서 확인할 방법과 커밋 메시지를 알려줘.
```

## 4. 버그가 났을 때

```
[무엇을 했더니] [무엇이 보였다] (기대: [무엇]).
로그/스크린샷: (붙여넣기)
원인을 먼저 추측만 해서 보여주고, 확인할 방법을 제안해줘. 고치기 전에 나한테 물어봐.
```

## 5. 성능이 느릴 때

```
Tracy 캡처에서 [구간]이 [n]ms 걸려. 예산은 docs/22_p0_tech.md 표 기준 [m]ms야.
원인 후보와 측정 방법을 먼저 제안해줘.
```

## 6. 기획을 바꾸고 싶을 때

```
[무엇]을 [어떻게] 바꾸고 싶어. 영향받는 코드와 문서를 먼저 찾아서 알려주고,
합의되면 docs/DECISIONS.md에 기록한 뒤 고쳐줘.
```

## 팁

- 한 단계가 끝나면 `/clear`로 대화를 비우고 다음 단계를 시작한다. 긴 대화는 품질이 떨어진다.
- 계획 모드는 Shift+Tab으로 켠다.
- 결과를 눈으로 확인해야 하는 작업(렌더링·애니메이션)은 스크린샷을 찍어 붙여주면 가장 정확하다.
- 참고 이미지·영상은 `docs/reference/`에, 동작 참고 구현은 `tools/motion_viewer/`에 있다.
