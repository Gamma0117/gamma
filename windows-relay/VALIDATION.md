# Windows 중계 검증 기록 — 2026-10-01

상태: 배포 준비. **실제 Windows 두 앱의 입력·전송은 미검증**입니다.

## 구현 범위

- 사용자 PC에서 동작하는 PowerShell + Windows UI Automation 중계입니다. 게임 구현 파일은
  수정하지 않았습니다. 설치한 중계가 Git 교환함을 감시하고 새 보고서의 ID·경로·역할·회신 계약을
  지정한 상대 앱 입력창에 전달합니다. 보고서 전문은 Git에 보관하며 본문을 명령으로 실행하지 않습니다.
- Claude가 P0-6을 구현하고 Codex가 독립적으로 검토합니다. Codex 최종 구현 통과가 오면
  Claude에 통과를 전달하고 종료합니다. 다음 단계는 시작하지 않습니다.
- 일반 Git 전송, 초안 보호, 중복 수신 방지, 전송 의도 먼저 기록, 불확실한 전송의 수동 확인,
  전송 횟수·시간 한도, 사용자 판단 대기, 중지 단축키, 재시작 시 정지를 넣었습니다.
- 최초에는 역사 전체를 재생하지 않고 가장 최근 보고서 하나만 반대편 앱으로 전달합니다.
  프로그램 준비 중 Claude가 완료 보고를 보내도 오래된 Codex 지시로 덮어쓰지 않습니다.

## 실제 실행한 검증

환경: 클라우드 Linux, 공식 PowerShell **7.4.6**. Windows PowerShell 5.1을 실행한 결과가 아닙니다.

| 검증 | 결과 |
|---|---|
| 실제 `Relay.Core.psm1` 상태·문자열 테스트 | 14개 통과 |
| 실제 공개 GitHub 교환함을 읽는 `Read-Mailbox.ps1` | 3개 검사 통과 |
| 전체 PowerShell 소스 구문 분석 | 오류 없음 |
| C# 5 + Microsoft .NET Framework 4.8 실제 참조 어셈블리 컴파일 | 경고·오류 없음 |
| 기존 Python 전송 도구의 로컬 bare Git 회귀 검사 | 통과 |

상태 테스트가 확인한 것은 Windows 경로 인자 인용, 역할별 라우팅, 허용되지 않은 ID·경로 거부,
이전 JSON 호환, 첫 실행 기준, 반복 poll 중복 방지, 도착 순서, 잘못된 묶음의 원자적 거부,
전송 중 재시작 시 uncertain 복구, 사용자 확인 후 재시도, 전송 직전 오류 보존, 한도 경계,
최종 통과 뒤 종료, 실제 사용자 판단 대기, UTF-8 원자적 상태 저장과 백업입니다.

Git 읽기 검사는 공백·한글이 있는 새 임시 경로에서 실제 교환함의 메시지를 읽고,
동일 커밋에서 재발행하지 않으며, 전용 캐시의 origin이 달라지면 fetch 전에 거부하는지 확인합니다.
캐시 외에 파일을 바꾸거나 GitHub에 테스트 보고서를 push하지 않습니다.

Python 회귀 검사는 로컬 bare 저장소만 사용합니다. 전문과 한글·리터럴 문자 보존, 동시 일반 push,
수신 ID 이후 회신만 읽기, 최종 통과와 사용자 판단 플래그의 올바른 전송을 확인합니다.
사용자의 Claude 환경에서 이 Python 실행을 다시 시도한 것이 아닙니다.

## 검증하면서 고친 것

- PATH에 Git 실행 파일이 여러 개 있으면 PowerShell의 Get-Command가 배열을 돌려줍니다.
  실행 경로가 하나의 잘못된 문자열로 합쳐지던 문제를 첫 Git 실행 파일만 선택하도록 수정했습니다.
- Enter 직전에 입력창 포커스·전면 창·수정 키·잠금 상태를 다시 확인합니다. 상태가 바뀌면
  자동 재전송하지 않고 확인 대기로 남습니다.
- 전송 후 앱이 입력창을 일시적으로 읽기 전용으로 바꿔도 비워진 내용을 확인할 수 있게 했습니다.
  입력 전에는 쓰기 가능한 빈 입력창을 요구합니다.
- 실제 사용자 판단을 요청하는 알림은 반대편 에이전트에게 의존 작업을 멈추도록 명시합니다.
- Windows PowerShell 5.1에서 한글을 읽을 수 있도록 배포 PowerShell 파일은 UTF-8 BOM을 넣었습니다.

## 미실행 범위

- Windows PowerShell 5.1 런타임에서 GUI 시작 및 종료.
- 사용자 버전의 Claude / Codex 데스크톱 앱에서 UI Automation 입력창 인식.
- 실제 클릭·한글 Unicode 키 입력·Enter / Ctrl+Enter 전송·원래 창 복귀.
- 여러 모니터·DPI 변경·앱 제목 변경·실제 앱의 최소화와 잠금·전역 단축키.
- 실제 앱의 보고서 게시와 상대 앱 깨우기가 반복되는 전체 과정.

C# 컴파일은 Windows API의 형식과 사용법을 검증한 것이며 Windows 실행 결과를 대신하지 않습니다.
최초 연결 시 `입력 위치 확인`과 첫 알림의 실제 도착을 확인해야 합니다. 자동 인식이 실패하면
정지하거나 사용자가 명시적으로 선택한 좌표 방식을 사용할 수 있습니다. 좌표 방식은 실제 전송을
확인하지 못한다는 제한을 UI와 안내에 표시했습니다.

실행·중지·복구 절차는 [README_KO.md](README_KO.md)에 있습니다.
