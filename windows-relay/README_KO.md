# Windows에서 Claude ↔ Codex 자동 진행

이 프로그램은 Git 교환함을 감시하고 새 보고서가 오면 반대편 **데스크톱 앱의 지정한 입력창**에
알림을 입력하고 전송합니다. 보고서 전문은 `codex/review-mailbox` 브랜치에 보관합니다.
현재 범위는 **P0-6 구현 → Codex 검토 → Claude 수정 → 재검토**입니다. 최종 통과를 Claude에
전달하면 종료하며 P0-7은 시작하지 않습니다.

클라우드에서 사용자 PC를 직접 제어하는 연결이 없으므로 아래 최초 실행은 PC에서 해야 합니다.
이후 매번 보고서 전문을 복사할 필요는 없습니다. 공식 Claude/Codex 내부 자동 실행 API가 아닌,
Windows UI Automation과 키보드 입력을 사용하는 별도 중계 프로그램입니다.

## 처음 실행: 약 2분

1. 두 데스크톱 앱에서 현재 Aurora 대화를 열고 입력창을 비웁니다. Claude와 Codex가 교환함을
   읽고 일반 Git push로 보고서를 게시할 수 있어야 합니다. 두 앱과 중계 프로그램은 일반 사용자
   권한으로 실행합니다. Git for Windows가 필요합니다.
2. `AuroraRelay.zip`을 다운로드합니다. ZIP 우클릭 → 속성 → **차단 해제**가 있으면 체크하고
   압축을 풉니다. 조직 정책이 스크립트를 금지하면 정책을 끄지 말고 관리자에게 문의하세요.
3. 압축을 푼 폴더에서 **Launcher.cmd**를 실행합니다. Windows 기본 PowerShell 5.1을 사용하며
   별도 Python, AutoHotkey, API 키는 필요 없습니다. 시스템 실행 정책은 변경하지 않습니다.
4. **1. Claude 연결**을 누른 뒤 4초 안에 Claude의 빈 입력창 안으로 마우스를 옮기고 기다립니다.
   클릭할 필요는 없습니다. **2. Codex 연결**도 같은 방식으로 합니다. 현재 대화를 유지하세요.
5. 각각 **입력 위치 확인**을 눌러 실제 입력창에 포커스가 가는지 확인합니다. 이 버튼은 메시지를
   입력하지 않습니다. 연결 시 기본 전송 키는 Enter입니다. 앱 설정이 Ctrl+Enter라면 해당 옵션을
   체크한 뒤 그 앱을 다시 연결합니다. 옵션은 앱별로 저장됩니다.
6. **3. 시작 / 재개**를 누릅니다. 첫 실행에서는 이전 보고서를 재생하지 않고 최신 보고서 하나만
   반대편 앱에 전달합니다. 현재는 Codex 회신을 Claude에 전달하여 P0-6을 이어가는 상태이며,
   그 사이 Claude가 완료 보고를 보내면 그 완료를 Codex에 전달합니다. 시작 알림이 불필요하면 첫 시작 전에
   해당 체크박스를 해제합니다.

감시는 기본 20초 간격입니다. 최근 3초 안에 사용자가 키보드나 마우스를 사용하면 전송을
기다립니다. 전송 중에는 앱을 잠시 전면으로 가져옵니다. UI Automation으로 입력문과 빈 입력창을
확인한 경우 원래 전면 창으로 돌아옵니다. 창을 닫으면 중계도 중지됩니다. 컴퓨터가 잠기거나
잠들어 있으면 전송할 수 없습니다.

## 중지와 오류 처리

- **Ctrl+Alt+F8** 또는 **일시정지**로 정지합니다. 이 단축키가 다른 앱과 겹치면 로그에 나오므로
  버튼을 사용하세요. 기본 한도는 실행당 20건, 180분이며 창에서 조정할 수 있습니다. 한도에
  도달하면 정지하므로 필요할 때 수동으로 재개합니다.
- 입력창에 초안이 있거나 창 제목·앱·입력 위치를 확인할 수 없으면 글을 덮어쓰지 않고 정지합니다.
  앱 UI나 대화가 바뀌었다면 올바른 입력창을 다시 연결하고 시작합니다.
- 전송 중 종료되거나 Enter 뒤 입력창이 비었는지 확인할 수 없으면 **자동 재전송하지 않습니다**.
  실제 앱을 보고, 이미 보냈으면 **전송됨 확인**, 보내지 않았으면 입력창을 비운 뒤
  **미전송: 다시 시도**를 선택하고 재개합니다. 입력창 비움은 UI에서의 전송 확인이며,
  서버가 보고서를 처리했다는 보장은 아닙니다. 다음 Git 회신으로 실제 진행을 확인합니다.
- 상태·연결 정보·로그는 `%LOCALAPPDATA%\AuroraReviewRelay`에 저장합니다. 종료 후 다시 열면
  항상 정지 상태입니다. 이 폴더를 지우면 이전 수신 기록도 지워지므로 문제 해결 중에는 보존하세요.
  상태 파일이 손상되면 임의로 초기화하지 않고 실행을 중단합니다.
- 엄격한 입력창 인식이 실패하면 **좌표 방식**을 선택하고 해당 앱을 다시 연결할 수 있습니다.
  이 방식은 입력 위치만 클릭하며 **초안·실제 전송을 확인하지 못합니다**. 지정한 창과 대화를
  유지하고 비어 있는 입력창을 직접 확인한 경우에만 사용하세요. 좌표 방식은 검증된 전송 대신
  `coordinate-attempt`로 기록됩니다. 기본값은 엄격한 UI Automation 방식입니다.
- 두 앱 자체의 사용자 판단·권한 차단·로그인 요구는 중계 프로그램이 승인하지 않습니다. 그런
  보고서는 `needs_user: true`로 전달하고 정지합니다. 중계 알림을 눌러 보내는 것과 권한 승인
  버튼을 누르는 것은 별개입니다.

## 보고서를 보내는 두 에이전트의 계약

각 알림에 Git 경로, 수신 ID, 작업 범위, 회신 절차가 포함됩니다. 파일과 명령으로 게임 작업 트리를
변경하는 구현은 Claude가, 계획·코드·실제 검증의 독립 검토는 Codex가 맡습니다. 에이전트가 작업을
마치면 요약만 보내지 말고 설명과 결과 **전문**을 별도 교환함 저장소에 추가하고 일반 push합니다.
외부 Python 실행이 차단된 Claude 환경은 `GIT_NATIVE.md`의 파일 편집·Git 절차를 사용합니다.

새 `.json`에는 기존 필드와 함께 아래 네 필드를 씁니다.

```json
{
  "work_scope": "P0-6",
  "stage": "implementation",
  "stop_cycle": false,
  "needs_user": false
}
```

`stage`는 계획이면 `plan`, 실제 구현 검토면 `implementation`입니다. `reply_to`는 읽은 메시지의
ID이며 `code_ref`는 검토할 실제 게임 커밋 전체 SHA입니다. 기존 메시지 파일은 변경하지 않고,
새 ID로 `.md`와 `.json`을 한 커밋에 추가합니다. 도착 순서는 Git 커밋 순서를 사용합니다.

Codex가 **P0-6 구현 최종 통과**를 보낼 때만 `status: "technical_pass"`,
`stage: "implementation"`, `stop_cycle: true`를 씁니다. 중계 프로그램은 그 통과를 Claude에
한 번 전달하고 종료합니다. Claude는 사용자에게 완료를 알리며 같은 통과를 재검토받는 보고서나
다음 단계 작업을 만들지 않습니다. 실제 사용자의 선택이 필요할 때만 `needs_user: true`입니다.

교환함은 공개 GitHub 브랜치입니다. 보고서에 인증 정보, API 키, 개인 정보를 넣지 않습니다.
프로그램은 고정 교환함에서 JSON과 보고서 존재만 읽으며 Git에서 내려받은 코드를 실행하지 않습니다.
설치된 이 프로그램 자체의 소스는 ZIP에 모두 포함되어 있습니다.

## 검증 범위

자동 수신·역할별 라우팅·중복 방지·전송 중 재시작·불확실한 전송·최종 통과·한도·UTF-8 상태 저장은
`tests/Relay.Tests.ps1`로 실제 PowerShell 모듈을 테스트합니다. Git 읽기는 실제 공개 교환함에서
확인합니다. 별도 검증 보고서에 실행 환경과 결과를 기록합니다.

클라우드 Linux에서 **Windows 두 앱의 실제 클릭·UI Automation·키 입력은 실행할 수 없습니다**.
처음 연결할 때 입력 위치와 첫 Claude 알림을 확인하세요. PowerShell 5.1 및 실제 앱 버전에서의
전송 성공을 클라우드 테스트 결과로 주장하지 않습니다.

개발용 상태 테스트 실행:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\tests\Relay.Tests.ps1
```
