## 3차 검토 조건 반영

1. **`neutralizedThrough`는 `max(기존 값, through)`로만 커집니다.** 작은 through가 범위를 줄이지 않습니다.
   - 회귀 테스트: `Neutralize(10)`, `Neutralize(3)`, `Input(10, jump)` 순서 → 입력 10은 중립으로 받습니다.
2. **정상 상태의 정의.** 정리 뒤 기록이 비었고 `lastInput == lastSentSeq`이면 정상입니다. 빈 기록 자체를 재동기화 사유로 보지 않습니다.
   - 공백(방어 경로)은 둘 중 하나일 때만입니다.
     - (a) 기록이 남았는데 첫 번호가 `lastInput + 1`이 아님
     - (b) 기록이 비었는데 `lastInput != lastSentSeq`
   - 스폰 직후 `lastSentSeq = lastInput = 0`은 정상입니다.
3. **`inputPauses`는 멈춤 상태로 들어갈 때 한 번만 셉니다.** 멈춤에서 나온 뒤 다시 가득 차면 새로 셉니다. 멈춰 있는 틱마다 늘지 않습니다.
4. 모델의 불변식은 실제 `ServerPlayer`, `LocalPlayer`, `MovementSampler`, LoopModel 테스트로 다시 확인합니다. 충돌, 중력, 보간 결과는 물리 통합 테스트로 따로 확인합니다.
5. **수치 정정.** ±30,000,000에서 double 간격은 2⁻²⁸ ≈ 3.73e-9입니다. ε = 1e-7은 그 약 27배입니다. 최소 크기에 대한 결론은 같습니다.

## 2. 이동 물리 (`stepPlayer`, 서버와 클라이언트가 같이 씀)

- 상자 크기는 폭 × 키이고, 위치는 발 중심입니다.
- 한 틱(dt = 1/20초)의 순서:
  1. 입력 방향 (strafe, forward) ∈ {−1, 0, 1}²를 yaw로 돌리고, 대각선은 정규화합니다.
  2. 목표 속도: 웅크리기 `sneak_speed`, 달리기 `sprint_speed`, 그 밖에 `walk_speed`.
     - 달리기는 sprint 입력, 앞으로 이동, 웅크리지 않음이 모두 참일 때입니다.
     - 웅크리기가 달리기보다 우선입니다.
  3. 수평 속도: `v += (목표 − v) × a`. a는 땅에서 `ground_acceleration`, 공중에서 `air_acceleration`.
  4. 틱 시작에 땅에 있고 jump가 참이면 `vy = jump_velocity`.
  5. `vy = max(vy − gravity·dt, −terminal_velocity)`.
  6. 쓸기 충돌로 이동합니다(3장). 필요하면 자동 오르기를 합니다.
  7. 고른 경로가 막힌 결과로 위치, 땅 판정, 속도를 갱신합니다.
- 웅크리기는 속도와 눈 높이만 바꿉니다. 충돌 높이는 그대로입니다. 가장자리에서 멈추는 기능은 P1로 미룹니다.
- 기본 수치(`movement.json`):

  | 항목 | 값 |
  | --- | --- |
  | 폭 × 키 | 0.6 × 1.8 |
  | 눈 높이 | 1.62 (웅크리면 1.27) |
  | 오르기 높이 | 0.6 |
  | 중력 | 32 |
  | 최대 낙하 | 78 |
  | 점프 | 9.8 (꼭대기 1.26블록, 검토에서 계산) |
  | 속도 (걷기 / 달리기 / 웅크리기) | 4.3 / 5.6 / 1.3 |
  | 가속 (땅 / 공중) | 0.5 / 0.05 |
- 결정성: 같은 코드, 입력, 블록이면 같은 결과입니다. 비트 단위 동일성은 같은 플랫폼, 같은 빌드, 같은 부동소수점 설정에서만 보장합니다.
- Tracy 존: 서버 "Player movement", 클라이언트 "Player prediction".

## 3. 충돌

- **ε 하나:** `kCollisionEpsilon = 1e-7` 블록.
  - 한 축의 겹침: `aMax − bMin > ε` 그리고 `bMax − aMin > ε`
  - 상자와 겹친 칸: `[floor(min + ε), ceil(max − ε) − 1]`
  - 청크 기둥: 칸 범위를 `>> 4`(음수는 floor)
- **쓸기:** 축마다(Y, X, Z) 시작부터 끝까지 지나가는 상자 전체에 겹치거나 닿는 모든 칸의 상자로 이동을 제한합니다. 이미 ε 넘게 겹친 상자는 그 축의 이동을 막지 않습니다(빠져나올 수 있음).
- **칸의 종류**
  - 불러온 기둥: y ≥ 320은 빈칸, y < −64는 꽉 찬 칸(메셔와 같은 "월드 아래는 막힘"), 그 사이는 상태의 상자 목록
  - 미로드 기둥: **높이와 관계없이 모든 칸이 꽉 찬 칸 (규칙 A, 벽)**
- **정지 (규칙 B):** 플레이어 상자와 양의 부피로 겹친 기둥 중 하나라도 미로드면 그 틱은 물리 없이 처리합니다.
  - 위치는 그대로, 속도는 0, `frozen = true`. 꺼낸 입력은 확인합니다.
  - 겹친 기둥은 크기 가정 없이 모두 계산합니다.
  - 경계에 정확히 닿은 것은 겹침이 아니므로, A로 막힌 뒤에도 뒤로 물러날 수 있습니다.
- **불러온 청크의 뜻:** 서버는 World의 Loaded 항목, 클라이언트는 스냅샷이 있는 청크(그리기 자격과는 무관)입니다. 두 쪽이 다르면 서버 결과로 보정됩니다.
- **자동 오르기**
  - 조건(모두 만족):
    - `step_height > 0`
    - 수평 이동이 막힘
    - 이번 틱의 dy ≤ 0
    - 틱 시작에 땅에 있었거나, 이번 틱에 아래가 막힘
  - 점프 시작 틱과 올라가는 동안은 제외합니다. 점프가 우선입니다.
  - 경로: 위로 min(오르기 높이, 천장) → X → Z → 아래로 (올린 만큼 + 원래 아래 이동)
  - 이 경로의 수평 이동이 더 길면 이 경로를 씁니다. 땅 판정과 속도는 고른 경로로 갱신합니다.
- **모양 계약:** 상자는 로컬 [0,1]³ 안, 유한, 축마다 크기 1/16 이상, 상태마다 16개까지입니다. 위반하면 덮어쓰기 함수가 오류를 반환합니다. 데이터의 모양 필드는 부분 블록 작업에서 추가합니다.
- **하한과 ε:** 플레이어 폭·키 ≥ 0.1, 상자 ≥ 1/16, 둘 다 ≫ 2ε이라 칸 범위가 비지 않습니다. ε은 월드 끝 간격의 약 27배입니다.

## 4. 서버 플레이어 (`ServerPlayer`, 20tps 권한)

**우편함**
- 한 송신자(메인 스레드)의 FIFO입니다. 메시지는 `Input(seq, intent)`와 `Neutralize(through)` 두 종류이고, 뮤텍스 아래 한 줄 대기열에 쌓입니다.
- 상태는 틱마다 최신 하나만 유지하는 슬롯입니다.

**API (`IntegratedServer`)**
- `sendPlayerInput(PlayerInput)`
- `neutralizeInputs(through)`
- `takePlayerState() → optional<PlayerState>`
- `setViewCenterOverride(optional<ChunkPos>)`. 기존 `setViewCenter`를 대신합니다.

**틱 순서 (실행한 서버 틱마다)**
1. **수신.** 우편함을 도착 순서대로 처리합니다.
   - 스폰 전 메시지는 버리고, `highestReceived`와 `lastInput`을 건드리지 않습니다.
   - `Input`: 번호가 `highestReceived` 이하이면 버리고 `staleInputs`로 셉니다(늦음·중복). 그 밖에는 대기열에 넣고 `highestReceived`를 갱신합니다. 번호가 `neutralizedThrough` 이하이면 의도를 중립으로 바꿔 받습니다.
   - `Neutralize(through)`: 대기열에서 through 이하를 중립으로 바꾸고(yaw·pitch 유지), `neutralizedThrough = max(기존 값, through)`.
2. **초과.** 대기열이 4개를 넘으면 앞에서부터 버리고 `droppedInputs`로 셉니다.
3. **월드.** 불러올 중심 = 스폰 전이면 spawnColumn 청크, 스폰 뒤에는 중심 지정이 있으면 그것, 없으면 플레이어 청크. 그다음 `World::update`.
4. **스폰.**
   - spawnColumn 청크와 이웃 8개가 Loaded가 된 첫 틱에 스폰합니다.
   - 발 높이 = 플레이어 상자와 겹친 기둥들의 높이맵 최대값 + 1(빈 기둥이면 −64)
   - 채우기 상태는 참, 기다린 틱 수는 0, 두 번호는 0.
5. **의도 선택.**
   - 대기열이 빔: 중립으로 진행하고 `starvedTicks`를 하나 올립니다. 채우기 상태를 켜고 기다린 틱 수를 0으로 둡니다.
   - 채우기 상태이고 대기열이 2개 미만이며 기다린 틱 수가 2 미만: 중립으로 진행하고 기다린 틱 수를 하나 올립니다(`primingTicks`).
   - 그 밖: 맨 앞 입력을 꺼내고 채우기 상태를 끕니다.
6. **물리.** 규칙 B면 정지 처리, 아니면 `stepPlayer`를 **정확히 한 번** 실행합니다. 입력이 없어도 중력과 충돌은 계산합니다. 이전 W나 점프는 되풀이하지 않습니다.
7. **게시.**
   - `lastInput = 대기열이 비었으면 highestReceived, 아니면 맨 앞 번호 − 1`
   - 불변식: 대기열의 모든 번호는 `lastInput`보다 크고, `lastInput`은 줄지 않으며, 그 이하의 원본은 다시 실행되지 않습니다.
   - `PlayerState{serverTick, lastInput, motion, frozen}`를 게시합니다.

**결과**
- catch-up 틱도 한 틱에 한 걸음입니다. 버린 틱에는 계산하지 않습니다(월드와 같음).
- 입력이 여러 개 와도 서버 시간을 더 진행하지 않습니다.
- 혼자 남은 입력은 도착 뒤 세 번째 틱 안에 적용·확인됩니다.
- 프레임 간격이 50ms보다 짧은 정상 흐름에서는 첫 적용 뒤 굶는 틱이 없습니다.
- **입력 검사:** 축 값은 −1, 0, 1로 자르고, yaw·pitch가 유한하지 않으면 그 입력을 중립으로 바꾸고 로그를 한 번 남깁니다.
- **통계(F3):** 스폰 여부, serverTick, lastInput, 대기 수, starved / priming / dropped / stale 횟수, frozen.

## 5. 클라이언트

**입력 허용 조건:** 포커스 있음, 마우스 잡힘, UI가 키보드를 원하지 않음, 자유 비행 아님, 최소화 아님. 모두 참이어야 합니다.

**`block()` (차단)**
- 점프 latch를 지우고 "이번 프레임에 차단 있음"을 표시합니다.
- 보낸 입력 중 아직 중립화하지 않은 범위가 있으면:
  - `neutralizeInputs(lastSentSeq)`를 보냅니다.
  - 자기 기록의 같은 범위를 중립으로 바꾸고 다시 계산합니다. 이것은 보정 횟수에 넣지 않습니다.
  - 같은 범위는 두 번 보내지 않습니다.

**앱이 `block()`을 부르는 곳**
- 프레임 시작의 포커스 상실
- 최소화 분기에 들어갈 때
- `handleInput` 뒤 `CursorController::takeReleased()`가 참일 때. Esc 뒤 같은 poll에서 다시 잡혀도 해당합니다.
- 프레임 끝에 허용 조건이 거짓일 때

**`endFrame(accepting, spacePressed)`**
- 직전 프레임 끝이 허용 상태, 이번 프레임에 차단 없음, 지금 허용 상태가 모두 참일 때만 Space 눌림을 기억합니다.
- 차단이 있었던 프레임의 눌림은 poll 안 순서와 상관없이 버립니다. 이미 지운 기억은 되살리지 않습니다.
- 계속 누르고 있는 키는 틱에서 허용 상태일 때만 `isKeyDown`으로 읽습니다. 다시 잡은 뒤에는 다시 누를 필요가 없습니다.

**InputState**
- 포커스를 잃으면 이미 기록된 키 눌림도 지웁니다.
- 포커스가 없는 동안의 키 눌림은 기록하지 않습니다.
- 같은 poll에서 포커스 상실 직전에 누른 F3·Esc도 버려집니다. 문서에 적습니다.

**번호와 확인**
- `seq`는 스폰 뒤 1부터 늘어나는 "실제로 만든 입력"의 번호입니다.
- 버린 클라이언트 틱이나 멈춘 동안의 틱은 번호를 쓰지 않습니다.

**`LocalPlayer`의 상태**
- 기준: 마지막 권한 상태
- 기록: `{seq, intent, 결과}`, `lastInput`보다 큰 것을 모두 보관. 자르지 않습니다.
- 보간 쌍: 앞과 현재

**새 상태가 왔을 때**
1. `serverTick`이 이미 받은 것 이하이면 무시합니다.
2. `lastInput` 이하의 기록을 지웁니다.
3. 정상 판정:
   - 기록이 비었고 `lastInput == lastSentSeq` → 정상입니다. 현재 = 서버 상태, 앞 = 서버 상태.
   - 첫 기록이 `lastInput + 1` → 서버 상태에서 기록 전체를 다시 계산합니다. 현재가 이전 예측과 1e-4블록 넘게 다르면 `corrections`를 하나 올립니다. 보간 쌍은 다시 계산한 결과로 정합니다: 현재 = 마지막 기록의 결과, 앞 = 그 직전 기록의 결과(없으면 서버 상태).
   - 그 밖(공백)은 방어 재동기화입니다.

**기록이 가득 찼을 때(40)**
- 새 입력을 만들지 않고 예측도 하지 않습니다(멈춤).
- 멈춤에 들어갈 때 `inputPauses`를 한 번 셉니다.
- 확인으로 자리가 나면 다음 틱부터 재개하고, 번호는 이어서 씁니다.
- 상태 하나마다 다시 계산하는 걸음은 최대 40번이고, 프레임마다 최신 상태 하나만 처리합니다.

**방어 재동기화 (계약상 생기지 않음)**
- 진입: 오류 로그 한 번, `boundary = lastSentSeq`, 기록 비움, `resyncs`를 하나 올림.
- 대기: 새 입력을 만들지 않습니다. 받은 상태마다 앞과 현재를 그 상태로 둡니다.
- 종료: `lastInput ≥ boundary`가 되면 `boundary + 1`부터 재개합니다.

**예측하지 않은 틱** (스폰 전, 멈춤, 재동기화 대기)에는 앞 = 현재로 둡니다.

**스폰**
- 첫 상태를 받으면 앞 = 현재 = 상태, `lastSentSeq = 0`으로 시작합니다.
- 그 전에는 입력을 보내지 않고, 카메라는 시작 자세입니다.

**클라이언트 틱 시계**
- `TickScheduler`(50ms, 밀린 틱 상한 3)를 씁니다. 상한 이하면 모두 실행하고, 넘으면 1틱만 실행하고 나머지는 버립니다(기존 정책 그대로).
- 이유: 클라이언트가 멈춘 동안 서버는 이미 중립으로 진행했습니다. 밀린 입력을 몰아 보내면 지연만 늘거나 초과로 버려집니다.

**보간과 카메라**
- `alpha = clamp(1 − (nextTickTime − now) / tickInterval, 0, 1)`
- 플레이어 모드의 카메라 위치 = mix(앞, 현재, alpha) + 눈 높이(서 있을 때와 웅크릴 때 사이도 보간)
- 시선은 프레임마다 마우스로 바로 돌리고, 틱에서 그 값을 입력에 싣습니다.
- 서버 보정은 순간이동입니다.

**자유 비행 (F3 체크박스)**
- 켜면: 카메라는 P0-5처럼 움직이고, 플레이어는 차단 상태(중립)이며, 서버는 카메라 청크를 중심으로 불러옵니다. 스폰 전에는 무시합니다.
- 끄면: 중심 지정을 지우고 카메라가 플레이어 눈으로 돌아갑니다.

**ServerPlayer\***
- 확인 번호: [1,2,4,3] → 1, 3, 4. [1,2,2] → 1, 2. 1~40과 40 중복 → 37~40
  - 확인한 번호 이하의 원본은 이후 실행되지 않음
  - 확인 번호는 줄지 않음
  - 각 번호는 최대 한 번 적용
- 스폰 전 메시지는 번호를 오염시키지 않음
- 입력 40개가 한 번에 와도 물리 걸음 수 = 실행 틱 수
- 공중에서 입력이 끊겨도 떨어지고 착지함
- W나 점프를 되풀이하지 않음
- 단발 W, 단발 점프, 마지막 중립 하나, Neutralize 뒤 남은 입력 하나 → [중립, 중립, 입력, …] 순서로 세 틱 안에 확인
- `Neutralize(10)`, `Neutralize(3)`, `Input(10)` → 입력 10은 중립
- 고정 시드의 무작위 조합에서 불변식

**IntegratedServer**
- 3×3이 불러와진 뒤 스폰, 스폰 전 중심 지정은 무시
- 불러오는 중심이 플레이어를 따라감
- 중심 지정으로 플레이어 청크가 내려가면 정지하고, 지정을 지우면 다시 움직임

**LocalPlayer\***
- lockstep에서 보정 0
- 확인 번호의 네 경우마다 기록이 정리됨
- 빈 기록이고 `lastInput == lastSentSeq`이면 재동기화가 아님
- 서버를 멈추면 40에서 멈추고(`inputPauses` 1회), 재개하면 [37..40]을 다시 계산한 뒤 41부터 진행
- 일부러 만든 공백 → 재동기화 → `boundary + 1`로 재개, `resyncs`가 틱마다 늘지 않음
- 오래된 상태는 무시
- 보정 뒤 `alpha = 0`과 `alpha = 1`의 위치가 다시 계산한 앞과 현재와 같음
- 예측하지 않은 틱에는 앞 = 현재
- 밀린 틱이 상한 3을 넘으면 1틱만 실행

**입력\***
- InputState: Space → 상실 → 복원 → 새 클릭 → 옛 Space는 없고 클릭은 있음. 복원 뒤 새 Space는 받음.
- 샘플러: 차단 원인 다섯 가지마다 latch를 지움
- LoopModel(실제 `CursorController`·`InputState`·샘플러):
  - 이미 잡힌 상태에서 같은 poll에 Space 탭 → Esc → 클릭, `isKeyDown(Space)`는 거짓 → 마지막 상태는 잡힘이지만 점프 없음, Neutralize가 나감
  - 직전 프레임에 기억한 탭도 지워짐
  - W를 누른 채 포커스를 잃고 최소화한 프레임에서 Neutralize가 나감

**이산 사건 모델 (`tests/client/loop_simulation`)\***
- 30/60/144fps × 여러 서버 위상에서: 물리 걸음 수 = 실행 틱 수, 버린 입력 0, 모든 입력이 한 번 적용, 첫 적용 뒤 굶은 틱 0

**통합 (실제 스레드, 창 없음)**
- 같은 `serverTick`의 상태가 일치
- 입력을 멈추고 기다리면 권한 상태로 수렴
- 실제 `World`·`ClientWorld` adapter를 거친 자동 오르기와 계단

**앱**
- 스크린샷(플레이어 장면)과 음성 대조군
